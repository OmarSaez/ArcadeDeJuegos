DOCUMENTACIÓN TÉCNICA: MÓDULO UNIVERSAL P2P (`p2p.js`) - Estándar Arcade
========================================================================
Versión: 3.0 (Arquitectura Modular Resiliente STUN + TURN/TURNS)
Fecha: Noviembre 2026
Estado: Estándar Oficial en los 18 juegos multijugador del Arcade

1. INTRODUCCIÓN
---------------
El módulo universal `/p2p.js` centraliza toda la conectividad multijugador WebRTC/PeerJS del Arcade en un único archivo independiente (separado del motor de audio `/sounds.js`).
Soluciona de raíz:
- Bloqueos en redes Wi-Fi con *AP Isolation* (Aislamiento de clientes) o routers sin *NAT Loopback*.
- Bloqueos de puertos UDP mediante retransmisión automática por servidores `TURN`/`TURNS` en puertos `80` y `443` (UDP/TCP/TLS).
- Colisiones de códigos de 4 letras en el servidor global de PeerJS mediante prefijos automáticos por juego (`ARCD_<JUEGO>_<CODIGO>`), manteniendo en pantalla únicamente el código corto de 4 letras.
- **Alfabeto Anticonfusión (`ACEFHJKMNPRTWXY3479`)**: Elimina automáticamente todos los números y letras que se parecen entre sí en fuentes arcade/pixeladas (`0/O/Q/D`, `1/I/L`, `2/Z`, `5/S`, `8/B`, `6/G`, `U/V`), garantizando que ningún jugador se equivoque al leer o dictar el código de sala.

2. DEPENDENCIAS EN CADA JUEGO
-----------------------------
Incluir en el `<head>` de cada juego multijugador:
```html
<script src="https://unpkg.com/peerjs@1.5.2/dist/peerjs.min.js"></script>
<script src="../../p2p.js"></script>
<script src="../../sounds.js"></script>
```

3. USO DE LA API GENÉRICA (`ArcadeP2P`)
---------------------------------------

### A. Crear Sala como HOST (`ArcadeP2P.createHost`)
Genera automáticamente un código limpio de 4 letras, aplica el prefijo del juego, reintenta solo si el código está ocupado (`unavailable-id`) y gestiona reconexiones:

```javascript
ArcadeP2P.createHost({
    game: 'MIJUEGO',
    peer: peer,
    onPeerCreated: (p) => { peer = p; },
    onOpen: (code) => {
        isHost = true;
        myId = code; // Código limpio de 4 letras (ej: "K7M9")
        document.getElementById('display-code').innerText = code;
    },
    onConnection: (conn) => {
        // Se ejecuta cuando el canal P2P con el cliente ya está abierto
        clientConns[conn.peer] = conn;
    },
    onData: (data, conn) => {
        handleHostData(conn.peer, data);
    },
    onClose: (conn) => {
        delete clientConns[conn.peer];
    },
    onError: (err, userMsg) => {
        alert("Error P2P: " + userMsg);
    }
});
```

### B. Unirse a una Sala como CLIENTE (`ArcadeP2P.joinRoom`)
Recibe el código de 4 letras escrito por el jugador, resuelve el namespace del juego, configura `reliable: true` + watchdog de timeout + ICE Restart automático:

```javascript
const code = document.getElementById('code-input').value.trim().toUpperCase();
ArcadeP2P.joinRoom(code, {
    game: 'MIJUEGO',
    peer: peer,
    onPeerCreated: (p, c) => {
        peer = p;
        if (c) conn = c;
    },
    onOpen: (c, myAssignedId) => {
        isHost = false;
        myId = myAssignedId;
        conn = c;
        conn.send({ type: 'JOIN', nick: myNick });
    },
    onData: (data) => {
        handleClientData(data);
    },
    onClose: () => {
        alert("El anfitrión cerró la sala.");
    },
    onError: (err, userMsg) => {
        alert("No se pudo conectar: " + userMsg);
    }
});
```


### D. Manejo de Conexión (Común)
Esta función unifica la lógica una vez que el "cable" está tendido entre los dos jugadores.

```javascript
function handleConnection(c) {
    conn = c; // Guardamos referencia global

    conn.on('open', () => {
        console.log("¡CONEXIÓN ESTABLECIDA!");
        
        // Host: Suele enviar la configuración inicial de la partida
        if (isHost) {
            conn.send({ type: 'INIT_GAME', config: { level: 1 } });
        }
        
        // AQUÍ: Ocultar Lobby, Mostrar Pantalla de Juego
        startGameUI();
    });

    conn.on('data', (data) => {
        // Router de mensajes
        switch(data.type) {
            case 'INIT_GAME':
                // Cliente recibe config
                setupLevel(data.config);
                break;
            case 'PLAYER_MOVE':
                updatePlayerPos(data.x, data.y);
                break;
            case 'GAME_OVER':
                showResult(data.win);
                break;
            default:
                console.log("Paquete desconocido:", data);
        }
    });

    conn.on('close', () => {
        alert("Rival desconectado");
        resetGame(); // Volver al menú
    });
    
    conn.on('error', (err) => console.error("Error en túnel de datos:", err));
}
```

4. BUENAS PRÁCTICAS Y ARQUITECTURA V3.0 (STUN + TURN + NAMESPACE EN SOUNDS.JS)
------------------------------------------------------------------------------
- **Inyección Automática en Todo el Arcade (`sounds.js` -> `ArcadeP2P`):**
  Al incluir `<script src="../../sounds.js"></script>`, el motor `ArcadeP2P` envuelve automáticamente `window.Peer` en todos los juegos del Arcade e inyecta:
  1. **Servidores STUN múltiples:** Google (`19302`) + Cloudflare (`3478`) para conexión directa ultrarrápida.
  2. **Servidores TURN / TURNS de respaldo:** PeerJS Cloud (`3478`) + OpenRelay (`80` UDP/TCP y `443` UDP/TCP/TLS) para atravesar redes Wi-Fi con *AP Isolation* (aislamiento de clientes), falta de *NAT Loopback* o Firewalls UDP estrictos.
  3. **Prefijo de Namespace Automático por Juego (`ARCD_<JUEGO>_<CODIGO>`):** El jugador sigue viendo e ingresando códigos limpios de 4 caracteres, pero en el servidor global de PeerJS se registra con prefijo único por juego para evitar colisiones mundiales.
  4. **Reconexión e ICE Restart Automático:** Mantiene vivo el WebSocket de señalización (`pingInterval: 5000`) y ejecuta `restartIce()` automáticamente si falla el primer intento UDP.
- **Cierre de Conexiones:** Siempre manejar `conn.on('close')`. Las redes móviles suelen cortar conexiones brevemente.
- **Reinicio:** Si se quiere reiniciar la partida, enviar un mensaje `{type: 'RESTART'}` en lugar de recargar la página, para mantener el túnel abierto.
- **Datos:** Enviar objetos JSON simples es lo mejor. Para juegos de acción (tiempo real), enviar solo los inputs o posiciones clave, no todo el estado del juego cada frame.

5. EJEMPLO DE FLUJO DE MENSAJES (BATTLESHIP)
--------------------------------------------
1. **Host** > `INIT` (GridSize, Configuración de Flota)
2. **Cliente** > `READY_FLEET` (Mi flota ya ubicada)
3. **Host** > `START_GAME` (O simplemente inicia el turno)
4. (Durante el juego) > `SHOT` {x, y}
5. (Respuesta) > `SHOT_RESULT` {x, y, hit: true/false, sunkId: null/id}
